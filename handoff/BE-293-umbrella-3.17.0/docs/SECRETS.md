# Secret Contract (names and keys only)

**Evidence:** the DEV revision 21 manifest, plus the key names of live Secrets in namespace `be293`, read-only on 2026-11-02. No value was read or stored.

**Two delivery paths:**

- **A. Pre-provisioned.** These Secrets must exist **before** `helm install`. The chart does not create them.
- **B. Chart-created.** Helm renders these from values. Every credential value comes from the secrets overlay (`values/values-be293-dev.secrets.example.yaml`, 125 placeholders). Several of these charts use `lookup` to keep an existing Secret. On an empty cluster they use the overlay values.

## C. Credentials that revision 21 passes inline (in Helm release values)

These are supplied through the secrets overlay as in DEV:

- `identity-and-trust-bundle.{identity-hub-postgres.identityhub,issuer-service.issuerservice}.env.EDC_IH_API_SUPERUSER_KEY`
- `identity-and-trust-bundle.identity-hub-postgres.identityhub.iatp.sts.oauth.client.{secret,x_api_key}`
- `portal.backend.processesworker.identityHub.{apiKey,issuerAdminApiKey}`, `portal.backend.processesworker.bpnDidResolver.apiKey`
- The EDC management API key and the connector DB password: `<alias>.dataspace-connector-bundle.tractusx-connector.controlplane.endpoints.management.authKey` and `….postgresql.auth.password`. Both come from the secrets overlay. They are rendered as **plain env values** in the EDC Deployments, exactly as in DEV. Here `<alias>` is `tx-data-provider`, `dataconsumerOne` or `dataconsumerTwo`.
- The EDC data plane proxy key (`TX_EDC_DPF_CONSUMER_PROXY_AUTH_APIKEY`) is **not** in the secrets template. Revision 21 uses the vendored Connector 0.13.0-rc2 chart's **embedded upstream default** (8 characters, publicly known), verified by render on 2026-11-02. To harden it, set `<alias>.dataspace-connector-bundle.tractusx-connector.dataplane.endpoints.proxy.authKey` in the private secrets overlay. That is a deliberate deviation from revision 21; see `BLOCKERS.md` S-03.

Recommendation for the target: apply `values-be293-identityhub-superuser-secretref.yaml`, which moves the first four groups to `identityhub-superuser`. The EDC keys stay inline until the Connector SecretRef work, which is out of scope here (`BLOCKERS.md` S-01).

## D. Never fill

`wallet.participants.*.vaultToken` and `wallet.identityHub.shared.vaultToken` must stay empty. The `k8s-dev-01` guard fails the render when they are set (static-token mode reads connector tokens from the `*-connector-crypto` Secrets).

## E. Check before install

```bash
ruby tools/make_synthetic_secrets.rb ...     # tests only
helm template ... -f <env>.private.yaml -f <real>.secrets.yaml [-f values/values-be293-identityhub-superuser-secretref.yaml] \
  | ruby tools/check_placeholders.rb          # must print placeholders=0 example-identifiers=0
```

Never pipe a render made with real values to a file, a log or a terminal you share.
