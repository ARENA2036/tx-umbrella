## 2. What the target profile enforces (fail closed)

- **Confirmed values:**
  - namespace `be293`, both as `.Release.Namespace` and as `be293.target.namespace`; `portal` and every other namespace are rejected;
  - ClusterIssuer `letsencrypt-prod`;
  - `storageClassPolicy: cluster-default`.
- **No DEV inheritance:**
  - any non-empty value in the `k8s-dev-01` `be293.platform` block is rejected;
  - so is `devVaultStaticTokens`, and a CoreDNS patch that is enabled or not explicitly disabled;
  - so are `letsencrypt-dev`, `premium-perf1-stackit`, `example.invalid`, `.tx.test` and `<<SET-BY-OPERATOR` anywhere in the merged values.
- **Storage:**
  - `global.storageClass` and the value behind each of the 14 rendered claims must be empty. Each path was verified by probing it. The two DEV keys that the IdentityHub and IssuerService charts ignore must be empty too;
  - `storageClass: "-"` is rejected anywhere, because it renders `storageClassName: ""`;
  - the post-render check then requires every rendered claim to carry **no** `storageClassName` key at all.
- **DNS and TLS:**
  - the DNS zone must be a valid DNS name that is not reserved (`.example`, `.invalid`, `.test`, `.local`, `.localhost`, `example.com/.net/.org`);
  - the wallet hosts must be `identity-hub.<zone>` and `issuer-service.<zone>`;
  - the ingress class is required, and `externalDns` must be an explicit boolean;
  - DID BPNs must match `BPNL` + 12 characters.
- **Images:**
  - registry and repository are required, and the repository must sit under the registry;
  - `privateImages` must match `be293.target`, with digest pinning on and no `pullPolicy: Never`;
  - the post-render check confirms all 14 private images use `<repository>@sha256:`.
- **Secrets and Vault:**
  - only pre-provisioned Kubernetes Secrets; External Secrets is off; Helm hooks must be approved explicitly;
  - the Vault address is required, and the auth mode is `secret-backed-static-token`;
  - no embedded Vault and no inline Vault token; an `EDC_VAULT_HASHICORP_TOKEN` SecretKeyRef is required on all 6 connector planes;
  - all in-cluster `*.svc.cluster.local` addresses must point to namespace `be293`.
- **Credentials:** each of the 124 credentials must be present and at least 16 characters long. Placeholders, `synthetic-` values and common weak words are rejected. A credential delivered through a SecretRef (the optional superuser overlay) may be absent inline, but any inline value that is still present gets the same checks. Values are never printed.

## 4. Remaining blockers

Inputs still needed from the target-cluster operator:

1. **DNS zone.** The DEV layout has two host families: `<svc>.<zone>` and `<svc>-<zone>`. The second covers `centralidp-`, `portal-`, `portal-backend-` and `sharedidp-`, and is kept as is. Confirm both families, public resolution, and certificate issuance for the DID hosts.
2. **Ingress class**, and whether **ExternalDNS** manages the records. The guard requires both explicitly. The controller must support the ingress-nginx `use-regex` annotation for the DID-document route.
3. **Image registry and repository** for the 14 private images, mirrored by digest (B-02). 10 of the 14 cannot be rebuilt from pushed source.
4. **imagePullSecret** name, pre-provisioned in `be293`.
5. **Vault:**
   - whether the release-local `be293-vault` is allowed, and its address;
   - unseal and bootstrap ownership, and the policy (B-03);
   - the BDRS token, which cannot renew itself (B-08).
6. **Credentials:** 124 values plus 13 pre-provisioned Secrets from the approved store, with matching OAuth client-secret pairs (B-06).
7. **Helm hook approval** (B-04, B-11). The empty-cluster install is not proven, so the isolated-cluster test must pass first.
8. **Default StorageClass:** confirm one class is marked default. Otherwise every claim stays Pending. Also confirm that it supports ReadWriteOnce and that about 77 GiB is available.
9. **New domain means new DIDs and credentials** (B-05). The live Keycloak and Portal state on DEV is not reproduced (B-09).
10. **Scope decisions:**
    - whether services other than the DID and StatusList hosts must be reachable from outside;
    - whether the DEV helpers `smtp4dev`, the test-data seeding and the Helm test Pods stay on the target.

Until items 1–8 and 10 are answered and the isolated-cluster test has passed, this package must not be used for an installation.
