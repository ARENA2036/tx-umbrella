# BE-293 Umbrella 3.17.0: `be293-target` profile

Chart `umbrella` `3.17.0-be293-target.1`.

> **Offline-validated, NOT installation-ready.** The tests below show that the chart renders, lints and fails closed using a test fixture and throwaway credentials. They do not prove that images pull, that DNS, certificates or Vault work, or that the hooks and services succeed on the cluster.
>
> Installation stays blocked until two things are done:
> - the operator inputs in [CHANGE-REPORT.md §4](CHANGE-REPORT.md#4-remaining-blockers) are resolved;
> - the isolated-cluster test (`../BE-293-umbrella-3.17.0/docs/ISOLATED-CLUSTER-TEST-PLAN.md`) has passed.

This package adds a fail-closed deployment profile for the confirmed BE-293 target cluster.

The verified DEV package `../BE-293-umbrella-3.17.0/` is not modified. This package reuses its Vault chart, secrets example, SecretRef overlay, inventories and tools.

## Confirmed target settings

The chart guard enforces these settings:

| Setting | Value |
|---|---|
| Namespace | `be293` (dedicated). `portal` and every other namespace are rejected. |
| ClusterIssuer | `letsencrypt-prod` |
| StorageClass | The cluster default. No `storageClassName` is rendered, including `""`, which would disable dynamic provisioning. |

## Contents

| Path | Purpose |
|---|---|
| `chart/umbrella/` | The verified chart, plus the `be293-target` guard (`templates/_target-validate.tpl`), the four external Ingresses (`templates/be293-target-external-ingresses.yaml`) and the credential contract (`files/be293-target-credentials.json`) |
| `values/values-be293-target.example.yaml` | Sanitized target overlay, generated by `tools/derive_target_example.rb`. It fails the guard on purpose. |
| `values/target-platform.example.yaml` | The platform inputs the operator must confirm. No credentials go in this file. |
| `tools/build_target_values.rb` | Builds the private umbrella and Vault overlays from the confirmed inputs |
| `tools/check_target_render.rb` | Post-render checks: storage, namespace, Ingress, issuer, images, placeholders |
| `tests/run_tests.sh` | Offline test suite: DEV identity, lint, positive renders, negative guard tests |

## Local validation for the cluster operator

Tested with Helm 4.3.0 and Ruby 2.6. Nothing contacts a cluster, and no real credential is needed.

```bash
cd handoff/BE-293-umbrella-3.17.0-target

# 1. Self-test of the package (fixture coordinates, throwaway random credentials)
bash tests/run_tests.sh                      # expect: ALL TESTS PASSED

# 2. Your confirmed platform coordinates (no credentials). The file name must end in .private.yaml.
cp values/target-platform.example.yaml target-platform.private.yaml
${EDITOR:-vi} target-platform.private.yaml
ruby tools/build_target_values.rb target-platform.private.yaml .verify/target

# 3. Throwaway credentials, ONLY to validate the platform coordinates offline (never deploy them)
umask 077; T="$(mktemp -d)"
ruby -rsecurerandom -e 'print File.read(ARGV[0]).gsub(/<<SET-FROM-SECRET-STORE:[^>]*>>/) { SecureRandom.alphanumeric(32) }' \
  ../BE-293-umbrella-3.17.0/values/values-be293-dev.secrets.example.yaml > "$T/throwaway.secrets.yaml"

# 4. Lint, render and check (the render stays in the temporary directory)
helm lint --strict chart/umbrella -n be293 -f .verify/target/values-be293-target.private.yaml -f "$T/throwaway.secrets.yaml"
helm template be293-app chart/umbrella -n be293 \
  -f .verify/target/values-be293-target.private.yaml -f "$T/throwaway.secrets.yaml" > "$T/app.yaml"
ruby tools/check_target_render.rb .verify/target/values-be293-target.private.yaml < "$T/app.yaml"
ruby ../BE-293-umbrella-3.17.0/tools/check_placeholders.rb < "$T/app.yaml"
helm template be293-vault ../BE-293-umbrella-3.17.0/charts/umbrella-infrastructure -n be293 \
  -f .verify/target/values-be293-target-vault.private.yaml \
  | ruby tools/check_target_render.rb .verify/target/values-be293-target.private.yaml --vault

# 5. Optional: move the shared IdentityHub super-user key to Secret identityhub-superuser
helm template be293-app chart/umbrella -n be293 -f .verify/target/values-be293-target.private.yaml \
  -f "$T/throwaway.secrets.yaml" -f ../BE-293-umbrella-3.17.0/values/values-be293-identityhub-superuser-secretref.yaml >/dev/null && echo OK

# 6. Remove the temporary directory (renders and throwaway credentials)
rm -rf "$T"
```

Expected results:
- `check_target_render.rb` prints `objects=235 claims=14 findings=0`, and `objects=6 claims=1 findings=0` for Vault.
- `check_placeholders.rb` prints `placeholders=0 example-identifiers=0`.

For an install, the throwaway file is replaced by the real secrets overlay from the approved secret store (`*.secrets.yaml`, git-ignored, passed as the last `-f`). The guard rejects any placeholder, `synthetic-` value, weak value, or credential shorter than 16 characters. It never prints a value.

Install order and hooks are unchanged from `../BE-293-umbrella-3.17.0/README.md`, with one difference: the four DID and StatusList Ingresses are part of the `be293-app` release, so `manifests/10-13` are **not** applied separately.
